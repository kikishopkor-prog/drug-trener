# Твой Друг Тренер — проект для Vercel

Готовое приложение на React + Vite + Tailwind. Вся логика — в `src/App.jsx`, картинки и иконки — в папке `public/`.

## Как выложить на Vercel (через GitHub, самый простой путь)

1. Зарегистрируйся на https://github.com и https://vercel.com (можно войти в Vercel через GitHub).
2. На GitHub нажми **New repository**, назови, например, `tvoy-drug-trener`, создай репозиторий.
3. Загрузи в него **содержимое** этой папки: на странице репозитория **Add file → Upload files**, перетащи `index.html`, `package.json`, `vite.config.js`, `.gitignore`, папки `src` и `public`. Нажми **Commit changes**.
   (Папку `node_modules` загружать не нужно — её нет.)
4. В Vercel нажми **Add New → Project**, выбери этот репозиторий, **Import**.
5. Vercel сам определит Vite. Настройки менять не нужно:
   - Framework Preset: **Vite**
   - Build Command: `npm run build`
   - Output Directory: `dist`
6. Нажми **Deploy**. Через 1–2 минуты получишь адрес вида `https://tvoy-drug-trener.vercel.app`.

Любое следующее изменение файла в GitHub автоматически обновляет сайт.

## Как запустить у себя (по желанию)

Нужен Node.js 18+ (https://nodejs.org).

```bash
npm install
npm run dev      # откроется http://localhost:5173
npm run build    # проверочная сборка в папку dist
```

## Перед тем, как давать ссылки клиентам

Переключатель «Клиент / Тренер» отключён (`DEV_SWITCHER = false` в `src/App.jsx`). Вход для тренера: `ваш-сайт/#admin`.

- **Без Supabase** (локальный режим): пароль — `change-me`, его нужно сменить (`ADMIN_HASH` в `src/App.jsx`, хеш SHA-256 нового пароля). Данные хранятся только в браузере, клиенты не видят твои программы.
- **С Supabase** (рекомендуется): вход по почте и паролю из Supabase, данные общие. Инструкция ниже.

## Подключение Supabase (общая база: тренер и клиенты видят одни данные)

Без этого шага приложение работает «локально»: данные лежат только в браузере. После подключения программы, веса, замеры и отметки синхронизируются между твоим телефоном и телефонами клиентов. Всё бесплатно (тариф Free).

**Шаг 1. Создай проект.** Зайди на https://supabase.com → Sign in with GitHub → **New project**. Название любое, придумай и сохрани пароль базы, регион выбери ближайший (например, Seoul или Tokyo). Нажми **Create new project** и подожди 1–2 минуты.

**Шаг 2. Создай таблицы.** В левом меню открой **SQL Editor** → **New query**. Открой файл `supabase/schema.sql` из этого проекта, скопируй ВСЁ его содержимое, вставь в окно и нажми **Run**. Должно появиться «Success. No rows returned».

**Шаг 3. Создай свой аккаунт тренера.** Левое меню **Authentication → Users → Add user → Create new user**. Введи свою почту и пароль (это и будет вход в кабинет тренера), поставь галочку **Auto Confirm User**, нажми **Create user**.

**Шаг 4. Закрой регистрацию для посторонних.** **Authentication → Sign In / Providers** (в старом интерфейсе — Settings) → выключи переключатель **Allow new users to sign up** и сохрани. Это важно: войти в кабинет тренера сможет только созданный тобой аккаунт.

**Шаг 5. Скопируй ключи.** **Project Settings** (шестерёнка внизу слева) → **API Keys** (или Data API): скопируй **Project URL** и ключ **anon public** (в новом интерфейсе он называется **Publishable key**). Эти ключи можно показывать в браузере, они не дают доступа к данным без ссылки клиента или входа тренера.

**Шаг 6. Добавь ключи в Vercel.** Открой проект в Vercel → **Settings → Environment Variables** и добавь две переменные (названия точно такие):

| Name | Value |
|---|---|
| `VITE_SUPABASE_URL` | Project URL из шага 5 |
| `VITE_SUPABASE_ANON_KEY` | ключ anon / publishable из шага 5 |

**Шаг 7. Обнови файлы на GitHub.** Загрузи в репозиторий новую версию проекта (Add file → Upload files, перетащи содержимое папки; файлы с теми же именами заменятся): новые `src/cloud.js`, `supabase/schema.sql`, `.env.example` и обновлённые `src/App.jsx`, `README.md`.

**Шаг 8. Пересобери сайт.** Vercel пересоберёт его сам после загрузки на GitHub. Если файлы не менялись, нажми **Deployments → ⋯ у последнего → Redeploy** (переменные подхватываются только при новой сборке).

**Шаг 9. Проверь.** Открой `ваш-сайт/#admin` и войди почтой и паролем из шага 3. Добавь клиента, скопируй его персональную ссылку и открой её на другом устройстве: клиент увидит свои тренировки, а его отметки появятся у тебя (обновление раз в ~15 секунд или при возвращении в приложение).

### Что важно знать
- Первый вход в пустую базу создаёт заготовки: 4 готовые программы, библиотеку упражнений и памятки. Тестовые данные, которые были у тебя в браузере, не переносятся.
- Пароль тренера теперь хранится в Supabase (смена: Authentication → Users). Строка `ADMIN_HASH` в коде в облачном режиме не используется.
- Ссылка клиента — это его «ключ». Отправляй её только ему. Если ссылка утекла, удали клиента или создай нового.
- Закрытие доступа клиенту (вкладка «Доступ») блокирует его кабинет и в облаке.
- Бесплатный проект Supabase «засыпает» после недели без активности. При регулярной работе этого не бывает, а если уснул — нажми Restore project в панели Supabase.
- Если пропал интернет, приложение покажет жёлтую плашку и отправит изменения, когда связь вернётся.

## Структура

```
index.html            страница, иконки, заголовок
package.json          зависимости и команды
vite.config.js        настройки сборки (React + Tailwind)
src/main.jsx          запуск приложения
src/index.css         подключение Tailwind
src/App.jsx           всё приложение (кабинеты клиента и тренера)
src/cloud.js          связь с Supabase
supabase/schema.sql   таблицы и функции базы данных (вставить в SQL Editor)
.env.example          пример переменных для Vercel
public/               фото тренера, иконки, скриншоты для онбординга
```
